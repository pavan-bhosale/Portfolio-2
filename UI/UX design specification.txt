# PAVAN BHOSALE

# EPIC INTERACTIVE PORTFOLIO

## UI / UX / MOTION / 3D DESIGN SPECIFICATION

**Document purpose:**
This document is the visual and interaction source of truth for implementing Pavan Bhosale's personal portfolio website.

The website is not intended to be a conventional portfolio.

It should feel like an **interactive digital journey through the evolution of a software developer**.

---

# 01 — DESIGN NORTH STAR

## Core concept

# PAVAN.OS

The website is conceptually an operating environment representing Pavan's technical journey.

It combines:

* premium editorial web design
* cinematic scrolling
* interactive 3D
* game-like progression
* spatial UI
* contextual cursor interactions
* AI/software visual language
* storytelling
* subtle futuristic aesthetics

The website should communicate:

> "You are not reading Pavan's resume. You are exploring Pavan's world."

# 17 — GLOBAL SCROLL PHYSICS

Use Lenis as the smooth scrolling foundation.

Scrolling should feel:

* fluid
* heavy enough to feel physical
* responsive
* controlled
* not sluggish

Avoid extreme scroll smoothing that makes the interface feel delayed.

Motion's scroll-linked system is appropriate for parallax, progress indicators and interactive storytelling, while scroll-triggered animation should be used for entering/leaving viewport states.

---

# 18 — SCROLL BEHAVIOR

There are two animation categories.

## Scroll-linked

Directly follows scroll.

Use for:

* camera movement
* parallax
* object rotation
* section progress
* horizontal movement
* scale
* depth

## Scroll-triggered

Starts when content reaches a threshold.

Use for:

* text reveals
* card entrances
* achievement activation
* content loading

Do not confuse the two.

---

# 19 — PARALLAX DEPTH

```text

```

This should be subtle.

The user should perceive depth rather than consciously noticing "parallax."

# 55 — MOTION PRINCIPLES

Motion should follow:

**slow → medium → fast**

Hierarchy:

Major transitions:
600–1400ms

Section reveals:
500–900ms

Cards:
250–500ms

Buttons:
150–300ms

Cursor:
50–150ms response with spring smoothing

Do not apply one duration globally.

# 56 — EASING

Linear is appropriate only when directly mapping to scroll.

# 60 — 3D PERFORMANCE RULES

3D is important, but performance is more important.

Spline's own guidance recommends reducing scene complexity and avoiding excessive embeds; its documentation recommends one or two embeds per page where possible and says not to exceed three embeds per page, while using the Spline Viewer when multiple embeds are needed because it supports lazy-loading.

Therefore:

DO NOT load every 3D scene simultaneously.

Use:

* dynamic imports
* lazy loading
* intersection-based activation
* scene cleanup
* reduced resolution on mobile

---

# 77 — PERFORMANCE BUDGET

The site must be visually ambitious without becoming unusable.

Priorities:

1. First Contentful Paint
2. Interaction readiness
3. smooth scrolling
4. 3D loading after initial content
5. progressive enhancement

Do not block the entire website on 3D.

The HTML/content should remain meaningful even before 3D finishes loading.

---

# 78 — ANIMATION PERFORMANCE

Prefer GPU-friendly properties:

```text
transform
opacity
clip-path
filter
```

Avoid continuously animating:

```text
width
height
top
left
margin
padding
```

Motion documentation specifically notes that properties such as opacity, transform, clip-path and filter can be GPU-accelerated and are preferable for smooth scroll-linked effects.

# 81 — Z-INDEX SYSTEM

Use a documented hierarchy.

Example:

```text
background      0
atmosphere     10
3d-scene       20
content        30
floating-ui    40
navigation     50
cursor         100
modal          200
```

Avoid random z-index values.

# 82 — SCROLL SECTION HEIGHT

Normal sections:

approximately:

Immersive scenes:


Only use very tall sections when the scroll interaction genuinely requires it.

Do not force users through huge empty spaces.

# 84 — INTERACTION FEEDBACK

Every interactive element should have at least one feedback channel:

Visual:

* scale
* glow
* color

Spatial:

* movement
* depth

Cursor:

* label

Motion:

* transition

Never rely on only color.

# 85 — DESIGN QUALITY CHECK

Before considering a section complete, ask:

### Visual

Does it look premium?

### Interaction

Does the interaction feel intentional?

### Narrative

Does this advance the story?

### Technical

Is the implementation efficient?

### Accessibility

Can users understand it without the animation?

### Mobile

Does it still work without hover?

If any answer is "no", revise the section.

---

# 86 — DO NOT OVERDESIGN

The most important restraint:

Do not use every effect available.

If a section already has:

* 3D
* parallax
* cursor interaction
* animated typography

do not additionally add:

* particles
* shaders
* magnetic cards
* glowing borders
* spinning objects
* scroll text

unless they provide a meaningful improvement.

# 91 — FINAL DESIGN PRINCIPLE

The website must never feel like:

"Here is my resume, but animated."

It must feel like:

**an interactive representation of Pavan's technical journey.**

3D exists to create spatial storytelling.

Motion exists to create continuity.

The cursor exists to create responsiveness.

Typography exists to create hierarchy.

Color exists to create meaning.

UI exists to communicate.

Every effect must support one of those purposes.

The final result should be:

# IMMERSIVE

# TECHNICAL

# CINEMATIC

# PERSONAL

# FAST

# ACCESSIBLE

# MEMORABLE

The goal is not maximum effects.

The goal is maximum **experience per interaction**.
